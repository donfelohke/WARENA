# WARENA Governance

## Purpose

WARENA develops and documents reproducible, maintainable, local-first computing systems and infrastructure. Shared ecosystem terminology and high-level decisions are governed by the [FELOH Corpus](https://github.com/donfelohke/feloh-corpus).

## Principles

1. Preserve human authorship and decision provenance.
2. Prefer inspectable, reproducible and repairable systems.
3. Record uncertainty and implementation status explicitly.
4. Use least privilege and minimise sensitive data.
5. Keep operational decisions reviewable and reversible where practical.
6. Support contributor onboarding and succession rather than permanent founder control.
7. Do not represent a design, configuration, or passing documentation check as proof of production operation.

## Change process

- Use a focused branch and pull request for substantive changes.
- Describe purpose, scope, risks, test steps, and expected evidence.
- Record the relevant commit and test result.
- Mark unverified behaviour as `UNKNOWN` or `NOT VERIFIED`.
- Link decisions that change canonical ecosystem concepts to the FELOH Corpus.

## Status labels

Use `LIVE`, `PROTOTYPE`, `RESEARCH`, `CONCEPT`, `HISTORICAL`, `SUPERSEDED`, or `UNKNOWN` as appropriate.

**ATTESTATION SPECIFIED ≠ EXECUTED.** A claim should be supported by a document, implementation, observation, record, and attestation appropriate to that claim.

## Scope boundaries

WARENA is the systems/infrastructure domain. NAKEBUSEN is the only ecosystem domain authorised to transact. Do not place private customer records, passwords, tokens, private keys, or other secrets in this repository.

This file documents governance intent. It does not assert that GitHub branch protection, security automation, or a formal maintainer council has been configured.
